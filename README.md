# 检验科知识库 App

以本院检验项目为核心，面向专业人士与患者的双入口知识库，通过已有微信公众号进入手机网页使用。

## 当前阶段

**产品规划与技术选型，尚未开始应用业务代码开发。**

当前仓库收录产品提纲和技术方案讨论稿，不含实际检验目录、患者数据或可运行的应用。没有初始化前端框架，也没有部署网站或接入公众号。

## 已确认的产品方向

- 入口选项卡固定为 **“我是专业人士”** 和 **“我是患者”**。
- 专业端侧重工作速查、本院开单名称、临床辅助选检及项目意义。
- 患者端侧重检查用途、检查准备、就检和报告安排、通俗解释。
- 第一阶段两个入口均免登录、不限制阅读，可随时切换。
- 后续再为专业人士入口添加查看要求，患者端继续公开。
- 两端共用同一份项目基础资料，分别组织专业扩展和患者说明。

## 技术方案建议

- **主要编程语言：TypeScript。**
- **界面框架与构建工具：Vue 3 + Vite。**
- **内容格式：JSON 管理结构化目录，Markdown 管理长篇说明。**
- **后续后台：需要专业端查看要求或在线维护时，再评估 Node.js + TypeScript 与数据库。**

以上为推荐方案，待用户确认后再初始化框架。当前没有安装项目依赖，不能将本文当作应用运行说明。

## 内容与版本管理

GitHub 用于保存、同步和追踪代码与经审查的内容版本；上传仓库不等于网页已上线。仓库可见性与应用前台是否公开是两个独立设置。

- 不提交患者身份、病历、个人检验报告、真实原始数据、账号凭证或未获批准的内部资料。
- 原始内部资料须先筛选公开范围，再转换为可发布条目；不要整包上传送检手册附件或内部系统导出。
- `.gitignore` 不能替代人工检查，提交前仍须核对暂存文件。
- 项目名称、开展状态、组合指标、标本要求与报告时效，以本院批准资料核实；临床选检内容需要专业审核。
- 尚未确定开源许可，不默认授予代码或医学内容的公开转载权。
