# 检验科知识库 App · 试验版

同一个手机网页应用，提供 **“我是专业人士”** 与 **“我是患者”** 两个阅读入口。当前两端均不限制查看；专业入口的查看要求留到后续阶段添加。

> **仅为功能与内容组织试验。** 文件依据和模型补充逐段标注，所有医学说明尚未完成医学审核。当前不是本院开单目录，不用于个体诊断或实际开单。

## 已实现

- 双入口及不同的阅读视图；切换时保留当前项目，支持键盘切换。
- 通用项目名称、缩写、别名搜索；专业分类与概述来源筛选。
- 项目详情、教材名称、PDF物理页码及核对用短引文。
- 文件/模型来源标记、待补内容统计；缺少本院文件的信息保留为缺项。
- 专业参考主题、患者准备指南、同设备收藏。
- 本地纠错草稿下载：**不自动提交**给医院或维护者，不收集患者资料。
- 加载失败重试、存储不可用降级、窄屏和系统深浅色适配。
- **九个手册分组、517条有名称记录**，原字段逐格保存，包括参考区间、临床意义、常规/急诊报告时间、标本要求、送检安排、组合内容与地点。
- **完整采集手册阅读**：233个标题段、21张表格、474个非表格正文块；可按章节导航、检索全文、从项目跳到原表对应行和下载原始Markdown。
- 目录按检验分组显示并分页；“同上”保留原词及本表同列定位，原文空白不补造，源文件校验失败可重试。

### 采集与临床意义速查增强

- **统一目录**：组合优先展示，可切换全部、组合、单项；输入成员缩写也能找到包含该词的组合。卡片直接显示原表标本要求，原有记录、收藏编号和教学内容不合并。
- **详情速览**：先显示“临床意义”，再显示“参考范围与解释”，随后显示标本要求和组合/细分项目关联；完整原字段与表后说明仍可展开逐格查阅。组合表没有临床意义时明确留缺，不把组合成员说明拼接成诊断结论。
- **六类常用采集入口**：临床化学、血常规、指定凝血项目、常规尿液、定时尿、常规粪便；摘录标注原书页、MD行号，测试逐字对照项目内原手册。通用章节不是单项特殊规则，不把常规尿套用到尿培养。
- **36个手册组合的原词索引**：仅在同一来源内匹配名称/缩写；唯一匹配可双向跳转，多重匹配列出候选，未匹配保留原词。CREA/CRE等缩写差异不自动猜测；同名索引并不确认方法、医嘱或标本等价，不能据此合管采样。
- **标本查询助手**：`/#/professional/specimens` 与 `/#/patient/specimens`。输入疾病、症状或项目关键词，在手册名称、临床意义、标本和组合原词中作本地文字检索；展示命中依据与来源定位，不调用模型、不生成个体化开检建议。多个词须同时命中；不能理解自然病史中的否定、时间和严重程度。
- 助手输入与页码只放本次页面内存，切入口/查看详情后返回可保留，改词重置页码、刷新即清空；不写入URL、localStorage或sessionStorage，不上传查询。组合成员与“同上”跳转保留原筛选及收藏/查询来源。请只填关键词，不填个人病历。
- 原始手册与现有项目字段不改写；本轮只增加原文件与来源链接，没有新增模型医学说明。临床内容仍需专业审核；来源统计不代表医学准确率。

## GitHub源码包与本地原件

仓库保持**私有**。上传程序、结构化内容、手册Markdown、来源索引与维护/验收文档；5份原始医学PDF不随Git上传。软件测试另使用Mozilla PDF.js公开的Basic API Test样例，不包含医学内容。

- 克隆源码后可以运行项目检索、手册文字阅读与界面功能；原PDF阅读需在本机恢复 `public/library/index.json` 所列文件并核对SHA-256。
- 默认 `pnpm check` 和浏览器回归仍要求完整本地原件。源码包模式由 **`CI_SOURCE_ONLY=true`** 显式启用：保留结构数据、手册全文、搜索、界面与公开PDF样例测试，只跳过明确需要本地教材原件的校验，不把跳过算作原件验证成功。
- GitHub Actions仅进行源码包模式检查。macOS/Linux可执行 `CI_SOURCE_ONLY=true pnpm check` 和 `CI_SOURCE_ONLY=true pnpm exec playwright test`；PowerShell先设置 `$env:CI_SOURCE_ONLY='true'` 再执行对应命令，结束后用 `Remove-Item Env:CI_SOURCE_ONLY` 恢复本地全量检查。
- `scripts/import-library.py` 使用只读盘点中的本机原件路径；其他电脑需要先核对资料位置。上传GitHub不是公众号部署，也没有把专业端变成受保护的线上服务。

## 本地运行

日常使用直接双击项目文件夹里的 **`打开检验知识库-macOS.command`** 或 **`打开检验知识库-Windows.cmd`**。启动后会自动打开浏览器；请保留最初的启动窗口，退出时按 Ctrl+C。首次安装、复制到其他电脑和常见故障见[打开软件说明](./打开软件说明.md)。这不是免环境的原生安装包，Windows 仍待实机验收。

以下命令供开发和检查使用：

支持 Node.js `^22.23.1`（22.x 中不低于 22.23.1 的版本），本机验证与 CI 均使用 `22.23.1`；其他主版本留待后续验证。使用 pnpm `11.17.0`（记录在 `packageManager`）。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

打开 **http://127.0.0.1:4317/**。该地址只供运行服务的电脑访问，不代表微信公众号已经上线。

生产构建预览：

```bash
pnpm build
pnpm preview --port 4318 --strictPort
```

## 检查命令

```bash
pnpm check                          # 类型、代码规范、单元测试、内容结构、生产构建
pnpm exec playwright install chromium webkit
pnpm test:e2e                       # Chromium 与 WebKit 的交互和视口检查
pnpm content:check                  # 允许显式标注模型补充的试验模式
pnpm manual:check                   # 全文校验值、全部项目/字段/表后说明与原文逐项对账
pnpm manual:import                  # 从项目内原文可重复重建手册记录，保留原有教学内容
pnpm content:check --require-documents
```

最后一条是未来全文件依据阶段的严格检查：**当前因仍有模型段落而按预期失败**，不是可以忽略的检查。只有逐条补齐依据后才能通过。

自动化浏览器检查不等于已经完成真实 iPhone/Android 微信客户端验收，也不证明医学内容已审核。

## 项目结构

```text
src/
  domain/       数据契约、检索、来源统计和规则，不依赖界面框架
  adapters/     HTTP资料读取、本地偏好存储
  state/        阅读工作区
  components/   双入口、条目卡、来源展示、纠错草稿
  views/        入口、列表、详情、主题、指南和来源进度页
public/content/
  catalog.json       通用目录、共用概述、文件来源、本院信息缺项
  professional.json  专业说明和参考主题，按需加载
  patient.json       患者说明和准备指南，按需加载
  xwh-manual-2026.md  用户指定手册的完整原文（只读快照）
public/library/
  index.json           全部主件、目录、页数和校验值
  *.pdf                本地只读原件副本（不纳入Git，未授权公开）
public/pdfjs/          从已安装依赖生成的本地阅读资源（启动/构建时准备）
scripts/
  validate-content.ts  混合来源/全文件依据检查
  import-manual.ts     可重复导入与原文完整性对账
```

项目字段采用结构化JSON。手册Markdown按已知格式安全解析为文字、上下标和表格；不执行源HTML，不使用 `v-html`。完整原文按需加载并验证SHA-256；未知章节和版本不一致均明确报错，不默默回退到其他内容。
