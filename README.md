# 检验科知识库 App · 试验版

手机网页应用，面向检验科专业速查。2026-09-19 起重构为单一专业入口（原患者入口已移除），界面参照知微手册：顶部全局搜索 + 功能模块页签 + 教材侧边目录树 + 密排正文。

> **仅为功能与内容组织试验。** 文件依据和模型补充逐段标注，所有医学说明尚未完成医学审核；教材为机器 OCR 转录，数值、公式、表格请回查原书。不用于个体诊断或实际开单。

## 功能模块

- **查项目**（`/#/items`）：528 条目录（517 条宣武医院2026采集手册原表照录 + 11 条通用教学条目，同名不合并），科室页签（9 个手册分组 + 教学参考）、全部/组合/单项筛选、密排行列表（40 条/页）、同设备收藏（`/#/saved`）。
- **查病种**（`/#/diseases`）：290 个病种索引、483 条项目关联，全部照录手册「临床意义」原文短引文与行号，按升高/降低/其他分组；病名是索引标签，不构成诊断或选检建议。项目详情页反向带「相关病种」入口。
- **读教材**（`/#/books`）：7 本教材/规程分章全文阅读，共 216 章 101,040 行原文。侧边书目/篇章节树、章内检索、按原书 PDF 页跳转、行锚点深链；545 条教材条目切片与项目目录双向互链。
- **采集手册**（`/#/manual`）：宣武医院2026手册全文（233 标题段、21 表、474 正文块），章节导航、全文检索、原表行跳转、原文下载。
- **资料库**（`/#/library`）：5 份主 PDF 共 2309 页，软件内按页阅读、缩放、跳页，按需分段加载。
- **全库搜索**（顶栏或 `/#/search`）：项目目录 + 手册全文块级命中 + 7 本教材逐行索引（39,467 条），⌘/Ctrl+K 唤起。
- **来源**（`/#/sources`）：跨文件一致性校验与来源覆盖统计（专业端口径）。

项目详情固定为 **临床意义 → 参考范围与解释 → 标本要求及其他资料**；手册条目保留完整原表字段、同上定位与表后说明，36 个组合的原词索引可双向查阅。本院业务字段（开单名称/代码/标本/时效/地点）在取得本院文件前已从界面隐藏，数据契约保留。

## 教材条目结构化与互链

`scripts/extract-book-items.ts` 按 OCR 标题文字模式重建逻辑层级（两种体例：测定类小节→条目→数字字段；条目→（X）字段小节），从 7 本教材切出 **545 条原文条目**（书92/96/97/98/99/100/101 分别 20/166/15/195/88/41/20 条），字段逐行照录、同名不合并、全部标注未校订。项目详情页与教材章节按**规范化全名精确匹配**（含手册照录别名；仅剥离「的测定/测定」程序性后缀，不猜缩写/近义）双向互链，可跳回原文章节行；当前 59 个目录项目命中、共 70 条链接。

## 病种关联库

`scripts/build-diseases.ts` 从 catalog.json 手册条目「临床意义」字段抽取病种提及：保守规则（宁可漏抽不造词），每条关联保留原文短引文与手册行号，病名只做索引标签。`validateDiseases` 跨文件逐字核对引文与行号，`diseases:check` 与源逐字节对账。

## 内容文件与 Git

- 入 Git：`catalog.json`、`professional.json`、`xwh-manual-2026.md`、`books.json`（教材清单与 SHA-256）。患者入口已移除，`patient.json` 不再使用（历史版本可从 Git 找回）。
- **不入 Git**：原始教材 PDF、`public/content/books/`（章节内容与检索索引、7 个 `book-*-items.json` 条目切片）、`public/content/diseases.json`（病种关联库）。本机首次使用运行：

```bash
pnpm books:import       # 7 本书分章 → 阅读/检索 JSON（源：~/Documents/资料库/检验科知识库，可用 LAB_LIBRARY_ROOT 改）
pnpm books-items:extract  # 7 本书条目切片
pnpm diseases:build     # 病种关联库
```

## 本地运行

日常使用直接双击项目文件夹里的 **`打开检验知识库-macOS.command`** 或 **`打开检验知识库-Windows.cmd`**。启动后会自动打开浏览器；请保留最初的启动窗口，退出时按 Ctrl+C。这不是免环境的原生安装包，Windows 仍待实机验收。

以下命令供开发和检查使用：支持 Node.js `^22.23.1`（22.x 中不低于 22.23.1 的版本，本机验证与 CI 均用 22.23.1），pnpm `11.17.0`。

```bash
pnpm install --frozen-lockfile
pnpm dev        # http://127.0.0.1:4317/
pnpm build && pnpm preview --port 4318 --strictPort
```

```bash
pnpm check                          # 类型、代码规范、118 项单测、内容/手册/教材/条目/病种对账、生产构建
pnpm exec playwright install chromium webkit
pnpm test:e2e                       # Chromium 与 WebKit（含 517 条手册详情、233 节原文逐格核对、病种与互链）
pnpm content:check                  # 允许显式标注模型补充的试验模式（含病种跨文件校验）
pnpm content:check --require-documents  # 全文件依据阶段检查（当前按预期失败：仍有模型段落）
pnpm manual:check                   # 手册全文校验值、全部项目/字段/表后说明逐项对账
pnpm books:check                    # 教材 224 个生成文件与源逐字节对账
pnpm books-items:check              # 7 本书条目与源对账
pnpm diseases:check                 # 病种关联库与源对账
```

`CI_SOURCE_ONLY=true` 时跳过需要本机教材原件/源库的校验（GitHub Actions 仅源码包模式；PowerShell 用 `$env:CI_SOURCE_ONLY='true'` 设置），跳过不算作原件验证。自动化浏览器检查不等于已经完成真实 iPhone/Android 微信客户端验收，也不证明医学内容已审核。

## 项目结构

```text
src/
  domain/       数据契约、检索、教材解析、来源统计和规则，不依赖界面框架
  adapters/     HTTP资料读取、本地偏好存储
  state/        阅读工作区（目录/正文/教材清单/来源QA/收藏）
  components/   条目概览、手册字段、组合关联、来源展示
  views/        项目目录/详情、书架/章节阅读、手册、资料库、收藏、搜索、来源
public/content/
  catalog.json       目录、共用概述、文件来源、本院信息缺项
  professional.json  专业说明，按需加载
  diseases.json      病种关联库（本机生成，不入 Git）
  xwh-manual-2026.md  用户指定手册的完整原文（只读快照）
  books.json          教材清单、章节与 SHA-256（入 Git）
  books/              章节内容与检索索引、条目切片（本机生成，不入 Git）
public/library/
  index.json           全部主件、目录、页数和校验值
  *.pdf                本地只读原件副本（不纳入Git，未授权公开）
public/pdfjs/          从已安装依赖生成的本地阅读资源（启动/构建时准备）
scripts/
  validate-content.ts     混合来源/全文件依据检查（含专业端口径与病种校验）
  import-manual.ts        手册可重复导入与原文完整性对账
  import-textbooks.ts     教材分章导入、逐行检索索引与对账
  extract-book-items.ts   6 本教材条目切片与对账
  build-diseases.ts       病种关联库构建与对账
```

手册与教材 Markdown 按已知格式安全解析为文字、上下标和表格；不执行源 HTML，不使用 `v-html`。手册完整原文按需加载并验证 SHA-256；教材生成文件与源逐字节对账。未知章节和版本不一致均明确报错，不默默回退到其他内容。

## 已知边界

- 完整原文件接入 ≠ 医学审核；教材条目为 OCR 标题模式化切片，遇原书体例变化可能漏切（以全文阅读为准）；病种关联为手册原文抽取的索引标签，未经医学审核，不构成诊断或选检建议。
- 手册的采集、送检与报告要求仅代表**首都医科大学宣武医院检验科**原文件，不代表用户所在医院制度。原表未给出医院开单代码，软件内部编号不能代替该代码。
- Windows 与真实手机微信客户端仍待实机验收；《全国临床检验操作规程》已完成 OCR 接入但未逐字校对（2015 年第 4 版，须结合现行规范）。
- 详细验收记录见 [UI重构与教材接入验收](./docs/审核/UI重构与教材接入验收-20260919.md)；历史记录见 `docs/审核/` 各轮验收。

## 内容维护与下一阶段

保留项目编号和段落编号，核对文件正文后逐条将 `model` 替换为 `document`，并填写来源、物理页和短引文。不能只改标签。

下一阶段仍需本地业务确认、专业医学审核、其余教材条目结构化复核、专业端准入规则及正式部署。手册组合表的具体项目按原文保留；唯一同名关联只服务于浏览，未确认的别名、歧义及缺失对应仍待人工核对，不擅自生成医嘱或修订原文数值。

专业正文当前公开按需读取，并非已经受保护。未来加限制必须改为服务端/受控内容服务校验，覆盖搜索、附件、直达链接和来源统计，不能只隐藏按钮或依赖本地阅读偏好。

GitHub用于私有版本管理；仓库是否公开与应用是否公开是独立设置。上传程序、结构化内容、手册Markdown、教材清单及必要文档，不上传原始医学PDF，也不公开部署；以后公开仓库或部署前须单独确认全文材料的公开范围。不要提交患者信息、凭证或未经授权的内部资料。项目本身的开源许可尚未确定，测试样例的上游许可证单独保留。
