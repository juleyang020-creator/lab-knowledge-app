## P2：详情与参考页重试沿用旧目录（已修复）

**位置**：`src/state/workspace.ts:84`、`src/views/DetailView.vue:73`、`src/views/ReferenceView.vue:44`。

**原因**：两处按钮只调用普通 `loadAudience`。该方法与 HTTP repository 都保留目录缓存，服务端目录补上新的来源后，重试仍用旧来源列表验证正文，所以可能持续失败。

**修法**：新增统一的 `retryAudience`，先调用已有的 `invalidateContent` 使两层内容缓存失效，再只加载当前入口。普通读取继续使用缓存，收藏、阅读偏好和无关存储不被清空，患者端不额外下载专业正文；继续沿用已有的代次/请求身份保护，避免旧请求覆盖新数据。

**验证**：

- `src/__tests__/ReadingRetry.spec.ts:12`：挂载真实 App、路由、工作区与 HTTP repository，覆盖患者/专业详情及患者指南/专业参考，共4条按钮回归。修复前全部因没有重新请求目录而失败，修复后通过。
- `e2e/reading-retry.spec.ts:5`：同样覆盖4条路由，在 Chromium/WebKit 两种浏览器中验证。包括数据未修正时继续报错、重试途中目录503、修正后恢复、不整页刷新、收藏与偏好保留、不额外读取另一个入口。
- 原有来源页重试、慢响应隔离、存储不可用等测试全部保留并通过。

上一轮 `independent-review-3.json` 保留为修复前的历史证据，没有把过去失败的记录改成通过。

## 双平台启动入口

| 文件 | 用途 |
| --- | --- |
| `打开检验知识库-macOS.command:1` | Finder/Terminal 双击入口，补充常用Node路径、定位项目目录、缺环境/失败时保留提示；已赋执行权限 |
| `打开检验知识库-Windows.cmd:1` | Windows 双击入口，切换到所在目录、检查Node、保留错误窗口；UTF-8无BOM、CRLF、关闭延迟变量展开 |
| `scripts/launch.mjs:15` | 检查Node范围与锁定依赖；仅在依赖缺失或安装锁文件变化时安装，不全局安装包管理器 |
| `scripts/launch.mjs:161` | 识别已有服务，限制等待时间，拒绝复用其他程序/其他项目副本 |
| `scripts/launch.mjs:180` | 先原子绑定 `127.0.0.1:4317`，再准备应用；同进程承载Vite，浏览器打开前确认就绪 |
| `打开软件说明.md:1` | 面向日常使用者的双击、退出、首次安装、跨平台复制和故障说明 |

主要行为：

1. 固定使用 `http://127.0.0.1:4317/`，不自动换端口，避免收藏因地址变化看起来丢失。
2. 重复双击只复用协议和真实项目路径身份均匹配的服务；端口冲突不擅自结束其他进程。
3. HTTP与Vite WebSocket复用同一个loopback监听；没有另开对外监听。
4. 运行当前源码而非已有 `dist`，不会打开旧构建。两个入口不是免环境的原生 `.app` / `.exe` 安装包。
5. 缺依赖时使用项目要求的pnpm和 `--frozen-lockfile --prod=false` 安装。若本机没有对应pnpm，借助npm临时运行指定版本，不升级全局版本。
6. 浏览器打不开时显示手动地址；保留原始服务窗口。关闭重复启动窗口不会停止主服务。

### 启动联调时发现并修正的问题

**P2：Vite客户端WebSocket连接异常（已修复）**。中间件模式下直接禁用WebSocket，真实浏览器会产生 `WebSocket closed without opened.`；不能只凭首页HTTP 200判定正常。当前将 `server.ws.server` 绑定到持有端口的HTTP服务。`e2e/launcher.spec.mjs:4` 在两种浏览器先复现失败，再验证无页面异常、能切换阅读入口、WebSocket与网页使用同一主机端口。
